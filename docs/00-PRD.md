# InternshipOS — Product Requirements Document

## Status
Draft for review

## Product
InternshipOS

## Vision
Help college students understand their internship readiness, identify what is missing, and know what to do next.

## Problem
Students preparing for technical internships often lack an objective, centralized way to compare their current capabilities and practical evidence against a target internship role.

## Primary Users
1st–3rd year college students preparing for their first technical internship.

## Core Differentiator
A claimed skill is not the same as demonstrated skill.

InternshipOS evaluates skills using evidence such as projects, GitHub repositories, hackathons/competitions, and certificates/coursework.

## MVP Target Roles
- Software Engineer Intern
- Backend Developer Intern
- Frontend Developer Intern
- Data Analyst Intern

## MVP Flow
Sign up
→ Profile
→ Target Role
→ Skills
→ Evidence
→ Readiness
→ Skill Gaps
→ Action Plan
→ Progress

## MVP Features
- Student account and authentication
- Student profile
- Target role selection
- Skill framework
- Evidence management
- Evidence assessment
- Transparent readiness assessment
- Skill-gap analysis
- Prioritized action plan
- Progress tracking
- Readiness history

## Out of Scope for MVP
- Job marketplace
- Internship scraping
- Recruiter accounts
- Mentor accounts
- Social network
- Chat system
- Resume builder
- Mock interviews
- Employer-facing verified readiness credential
- Leaderboards
- Black-box AI grading
- File uploads

## Product Principle
The readiness result is an evidence-based estimate for self-improvement, not a claim of objectively measuring a student's true ability.

## Public Product Experience
The deployed application should be accessible through a public URL.

Recruiters and visitors should be able to explore a polished read-only demo without needing to create an account.

## Design Direction
Premium, professional, responsive, 3D-enhanced and scroll-driven.

Approved visual direction:
The Mark — Assay / Verification / Foundry.

The product must not use the generic blue/purple AI/SaaS aesthetic.

## Quality Goals
- Professional visual identity
- Strong recruiter impression
- Clear UX
- Responsive desktop/tablet/mobile experience
- Accessible interaction
- Fast initial load
- Purposeful 3D
- Maintainable architecture
- Clear documentation
- Professional Git history

## Success Criteria
A new user should be able to:
1. Create an account.
2. Complete a profile.
3. Select a target role.
4. Add skills and evidence.
5. Run a readiness assessment.
6. Understand why the result was produced.
7. Identify priority gaps.
8. Receive actionable tasks.
9. Track progress.
10. Reassess after adding new evidence.
